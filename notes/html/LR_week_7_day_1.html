I. Akaike information criterion (AIC)

Carried over from the end of Week 6, Day 2:

−2ℓ(β^,σ^2)= nlnSSEp −nlnn +nln(2π) +n

Idea. The log-likelihood is biased / optimistic, because the estimates are based on our sample — the model has already been tuned to the very data we are scoring it on. So do a bias correction.

AIC= −2ℓ(θ^) +2(p+1)

Aside: ordering the criteria by model size

R2< Ra2< Cp,AIC< BIC

Read left to right this is an arrow from the biggest model to the smallest model. R2 keeps everything; adjusted R2 trims a little; Cp and AIC trim more and sit at roughly the same place; BIC is the most aggressive and returns the smallest model.

II. Bayesian information criterion (BIC)

BIC= −2ℓ(θ^) +(p+1)lnn

Lower is better here too. The marked term is (p+1)lnn, and the note on it reads: grows more quickly than AIC, so penalizes more heavily.

AIC versus BIC

What each criterion is actually trying to do
AICBIC
Goal Find the model that predicts best. Find the true model.
Model size Chooses larger models. Smaller models.
Weak predictors Keeps junk predictors. Drops weak (“good”) predictors.

How to use them

  • Must use the same data when comparing models.
  • The raw value doesn't matter — use them for ranking.
  • AIC and BIC might disagree.

Stepwise methods

  • Forward: add the predictor that drops SSE most, keep going until some threshold.
  • Backward: fit the full model, drop the weakest predictor, keep going.

Why we don't use these

  1. Computationally expensive.
  2. Greedy — always picking the best predictor, so it could miss other pairs that are good together.
  3. Invalid p-values — using the same data multiple times.
  4. Unstable.
  5. Overfitting — artificially good metric.

IV. Prediction sum of squares (PRESS)

  1. Let i=1.
  2. Drop observation i from the data.
  3. Fit the model on the remaining observations.
  4. Predict y^i.
  5. Take (yi−y^i)2.
  6. i=i+1 and repeat steps 2–5.
  7. Sum the squared errors.

Note: this is leave-one-out cross-validation.

PRESS= ∑i=1n (yi−y^i(i))2 = ∑i=1n (ei1−hii)2
The two annotations under that identity
PieceWhat the note says
y^i(i) y^ for the model fitted without observation i
1−hii higher leverage = harder to predict when left out of the model

The right-hand form is what makes PRESS cheap: you get all n leave-one-out predictions from a single fit, by dividing each residual by 1−hii, rather than refitting the model n times.

V. Warnings

  1. Selection bias — always choosing the “best” model.
  2. Multiple testing — selecting for small p-values.
  3. Multicollinearity — if X1 and X2 are highly correlated, model selection chooses one arbitrarily.

VI. Solutions

  1. Use cross-validation or a hold-out set.
  2. Remove correlated predictors first.
  3. Keep predictors if it makes sense.
  4. If you have X12 or X1X2, keep the main effects.
  5. If n≫p, keep all predictors that make sense.

VII. Logistic regression

The response is now binary: Yi∈{0,1}. So Y is an n×1 vector of 0s and 1s, while the design matrix X is n×p exactly as before — a column of 1s followed by X1,…,Xp−1.

Yi∼ Bernoulli(πi)

Why not use linear regression?

Suppose we tried the usual model anyway,

Yi= β0+ β1X1i+ ⋯+ βp−1X(p−1)i+ εi = XiTβ+εi

so that πi=XiTβ. Three things go wrong.

① Errors are binary, not Normal. Since εi=Yi−XiTβ, there are only two possible values:

The error takes one of two values, so it cannot be Normal
Ifthen
Yi=1 εi=1−XiTβ
Yi=0 εi=−XiTβ

② Variance is not constant. Var(Yi)=πi(1−πi) — it depends on πi, and therefore on X. Homoskedasticity is gone.

③ Constraints on the response. 0≤πi≤1, but a straight line is unbounded.

Long description of Figure 36

The horizontal axis is X and the vertical axis is Y, with 0 and 1 marked. Because the response is binary, every observation sits on one of exactly two horizontal rows of dots: a row at height 0, running from the left across to about two-thirds of the way along, and a row at height 1, starting about a third of the way along and running to the right. The two rows overlap in the middle, which is the region where the outcome is genuinely uncertain.

Two fits are drawn through those points. The dashed line is an ordinary least-squares fit. It is below 0 at the left-hand edge and above 1 at the right-hand edge, so at both ends it is predicting a probability that cannot exist — those regions are shaded and labelled "impossible: above 1" and "impossible: below 0". The solid S-shaped curve is the logistic fit. It starts just above 0, rises steeply through the overlap region, and flattens just below 1, never leaving the permitted band.

That is the whole argument for the logistic model: it is not that the straight line fits badly in the middle, it is that the straight line has no mechanism to stop, so it must eventually produce nonsense. Dashed versus solid carries the same distinction as the two pen colours in the original, and the shaded bands reproduce the highlighter.

The logit link

We need a function mapping πi onto a line — something that takes the interval [0,1] and stretches it over the whole real line. Two steps get us there:

odds= πi1−πi ∈(0,∞)
log odds= lnπi1−πi ∈(−∞,∞)

Taking odds removes the upper bound; taking logs removes the lower one. Setting that equal to the linear part gives the model:

logit(πi)= lnπi1−πi = XiTβ
The two names annotated on that equation
PartNameWhat it does
logit(πi) link function maps πi onto XiTβ
XiTβ linear predictor the familiar linear combination of the predictors

Solving back for πi:

πi= eXiTβ 1+eXiTβ = 1 1+e−XiTβ

This is the logistic / sigmoid function — the solid curve in Figure 36. Whatever value the linear predictor takes, the output is trapped strictly between 0 and 1, which is exactly the property the straight line lacked.
